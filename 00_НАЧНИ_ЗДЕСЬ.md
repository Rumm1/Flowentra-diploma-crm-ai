**Срок: 24 октября 2026 года.** Проект: *Development of a Business Management and CRM Platform with an Embedded AI Assistant*.

Это отдельный дипломный проект, не репозиторий QEDNEX. Документация для защиты подготовлена на английском; этот файл служит краткой инструкцией на русском.

## ЧТО ОБЯЗАТЕЛЬНО ДЕЛАТЬ САМИМ ДО 24 ОКТЯБРЯ

1. **Пользователи.** Провести и записать 3–5 реальных разговоров с представителями целевой аудитории ИЛИ получить содержательное согласование с реальным заказчиком. Записать дату, роли, вопросы, наблюдения/предположения, согласие на запись/использование. Нельзя выдумывать интервью.
2. **Научный руководитель.** Показать пакет Gulnur Shuteyeva, получить **реальные** комментарии, записать конкретные изменения и соответствующие коммиты в `docs/11_Supervisor_Feedback.md` и `plans/Feedback_Log_Template.csv`.
3. **GitHub или GitLab.** Создать реальный репозиторий, предоставить доступ всем участникам и руководителю; открыть доступ комиссии к моменту защиты. Выкладывать осмысленные изменения поэтапно. Нельзя создавать фиктивную историю коммитов.
4. **YouTrack.** Создать настоящий проект, перенести приоритетные задачи из `plans/YouTrack_Backlog.csv`, назначить исполнителей, критерии приёмки, сроки; связать реальные ветки/PR с ID задач.
5. **Индивидуальный вклад.** Каждый участник со своего аккаунта должен добавить **реальную** работу, участвовать в ревью, уметь показать соответствие задаче, коммиту и результату.
6. **Tag.** Когда пакет актуализирован, реальные ревью выполнены и версия готова, создать тег `pre-defense-1` на согласованном коммите. Не утверждать, что он уже существует.
7. **Статус.** Заменить `[NOT PROVIDED]` и `[NOT RECORDED]` в `SUBMISSION_STATUS.md` только проверенными фактами, включая ссылки.

## Как пользоваться пакетом

- Для руководителя/комиссии: начать с отчёта DOCX/PDF и PPTX.
- Для изучения UX: открыть `prototype/index.html`; все данные синтетические, после перезагрузки сбрасываются. Это не настоящее React-приложение, не реальная БД и не доступ к LLM.
- Для правки архитектуры: изменить `.dot`/`.puml` и заново экспортировать схемы. Наличие PNG/SVG не заменяет редактируемые исходники, поэтому сохранены оба формата.
- Для совместной работы: создать задачи в YouTrack и вносить изменения через отдельные ветки, Pull Requests/Merge Requests и ревью.
- Для проверки полноты: открыть `docs/00_Submission_Checklist.md`.

### GitHub: один запуск после авторизации

Этот Git-ready архив уже содержит `.git` и один начальный коммит от имени **AI-assisted draft preparation**, а не от имени кого-либо из команды. Для создания настоящего закрытого GitHub-репозитория на Windows прочитайте `GITHUB_И_СДАЧА_ЗАВТРА.md` и запустите `PUBLISH_TO_GITHUB.ps1` с GitHub CLI. Логин в GitHub должен выполнить владелец аккаунта. Дальнейшие задачи выполняются разными участниками в отдельных ветках с настоящими ревью. **Не выполняйте тегирование до финальной проверки:**

```bash
git tag pre-defense-1
git push origin pre-defense-1
```

## Честные ограничения

- Содержимое отчёта — начальный проектный план, а не фактически созданное приложение.
- Научный обзор и анализ конкурентов не подменяют наблюдения за реальными пользователями.
- Метрики и пороги в Test Plan — **цели**, а не измеренные результаты.
- Фактические интервью, согласие заказчика, обратная связь руководителя, история Git и задачи в реальных внешних сервисах не созданы этим архивом.
