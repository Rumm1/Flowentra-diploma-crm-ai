# Contribution guidelines — honest project history

- Use **your own** GitHub/GitLab identity and configured real email. Do not share accounts or backdate work.
- Record a real issue first (YouTrack) with one owner, acceptance criteria and deadline.
- Create a branch using the real issue ID once available: `DIP-23-database-schema`.
- Make coherent commits that identify changes accurately; document both design and code work.
- Open a Pull/Merge Request with that issue ID, changes made and test evidence. A **different team member** reviews it before merging to the protected baseline.
- If a task is blocked, leave it open and document the blocker. Do not mark as Done from planned prose alone.
- Keep private interview notes, credentials, API keys and real client personal data out of version control.
- Document how to run code and tests once implementation exists; the present archive contains a frontend **prototype**, not Go+React production code.
